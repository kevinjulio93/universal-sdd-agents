# Specification Procedure

Read approved requirements/architecture and existing spec conventions. Update the
assigned spec/** files with scope, stable acceptance IDs, contracts, failure cases,
test requirements, risks and unresolved questions. Reuse existing filenames and
revise the active spec instead of creating duplicates.
For AI/automation specify output/tool boundaries, budgets, PII policy and remote
side-effect approvals; distinguish offline checks from authorized live checks.
Return paths and proposed G0 checks to orchestrator. Planner owns scheduling and
task routing; architect owns decisions. No shell, check execution or delegation.
